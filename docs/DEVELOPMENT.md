# Developer setup (macOS, from a blank machine)

This takes a new Mac (Apple Silicon) with nothing installed to a working Nestbox dev environment. You can run the
tests, run the daemon and aligner, change the protobufs, and build the visualizer, desktop app and C# client.

The steps were checked on 2026-10-12 against a fresh clone of `armdemo` on macOS 26 (Python 3.13.4, protoc 36.2,
Node 24, .NET SDK 8). Anything marked *(not verified)* wasn't run.

## What's in the repo, and what you need for each part

| Part | Path | Needs |
|---|---|---|
| Core library, aligner, daemon, tests | `python/` | Python 3.13, `protoc`, Redis |
| Wire format | `protos/twig.proto` | `protoc` (compiled into Python and C#) |
| Browser visualizer | `visualizer/flaskapp/`, `ui-core/`, `libs/` | Python env, Redis |
| Desktop (Electron) app | `desktop/electron-app/` | Node.js |
| C# client (used from Unity) | `csharp/` | .NET 8 SDK, `protoc` |

Most active work happens in `python/`. Start with sections 1–4, and add the others when you need them.

---

## 1. Base tools

Open **Terminal** and run each of these.

```bash
# Apple command-line tools (git, compilers). Accept the dialog that pops up.
xcode-select --install

# Homebrew (package manager). Afterwards, follow the "Next steps" it prints to add brew to your PATH, then open a new terminal.
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Everything else the repo uses
brew install python@3.13 protobuf redis node gh
brew install --cask dotnet-sdk          # only needed for csharp/
brew install --cask visual-studio-code  # optional editor
```

Check:

```bash
python3.13 --version   # 3.13.x
protoc --version       # libprotoc 36.x (see "protoc version" below)
redis-server --version
node --version         # 20+
dotnet --list-sdks     # 8.x
```

**protoc version.** The Python runtime is pinned at `protobuf==7.36.2`. Python code generated by protoc **36.x**
matches that version. Code from a newer protoc than the runtime fails at import with a "gencode version" error. If
Homebrew has moved past 36, either pin the runtime to match in `python/requirements-armdemo.txt` or install a matching protoc.

## 2. Get the code

```bash
gh auth login                      # GitHub account with access to dgretton/nestbox
mkdir -p ~/code && cd ~/code
gh repo clone dgretton/nestbox
cd nestbox
git checkout armdemo               # active branch; main is well behind
```

Use a path that **isn't** synced by Dropbox or iCloud. Sync clients fight with `.venv` and `node_modules`.

## 3. Python environment

Create a virtualenv at the repo root, install the pinned dependencies, and install the package in editable mode:

```bash
cd ~/code/nestbox
python3.13 -m venv .venv
source .venv/bin/activate          # do this in every new terminal you use for Nestbox
pip install --upgrade pip
pip install -r python/requirements-armdemo.txt pytest
pip install -e python              # makes `import nestbox` work from anywhere
```

- `requirements-armdemo.txt` has the exact versions known to work.
- `requirements.txt` has loose lower bounds and is what `setup.py` uses.
- Torch is the big download, about 1 GB.
- Ignore the old `python/venv/` if a copy has one. It points at a Python that no longer exists.

### Generate the protobuf code (required)

The generated Python file `python/nestbox/proto_generated/twig_pb2.py` is **gitignored**. On a fresh clone,
`import nestbox` fails with `No module named 'nestbox.proto_generated.twig_pb2'` until you run:

```bash
sh protoc_python.sh                # run from the repo root
```

Run it again whenever `protos/twig.proto` changes.

## 4. Run the tests

The self-contained tests need no daemon or Redis. They take about 1.5 minutes:

```bash
cd python
python -m pytest -q nestbox/test_gauss_newton_aligner.py nestbox/test_bearing_measurement.py \
                    nestbox/test_twig.py nestbox/test_optimized_transformer.py
# expect: 22 passed
```

The other `test_*.py` files in `python/nestbox/` aren't pytest tests. They're scripts you run by hand, many of them
against a running daemon (next section). `test_armdemo_alignment.py` also needs calibration data from
`../arm-demo-20261003/`, which isn't in this repo.

## 5. Run the daemon and aligner

The daemon is a Flask server that owns the aligner. The aligner thread publishes its state to Redis, which needs to be running.

Terminal 1, Redis (in-memory, no dump files):

```bash
redis-server --save "" --appendonly no
```

Terminal 2, the daemon. Use the arm-demo config: it uses the deterministic Gauss-Newton aligner and serves plain HTTP
on `127.0.0.1:8650`. Start it from **outside** the repo, so stray files don't land in the working tree:

```bash
source ~/code/nestbox/.venv/bin/activate
export NESTBOX_CONFIG=~/code/nestbox/config/armdemo_config.yaml
cd ~ && python -m nestbox.networking.daemon_server --config-path "$NESTBOX_CONFIG"
```

Terminal 3, a client:

```bash
source ~/code/nestbox/.venv/bin/activate
export NESTBOX_CONFIG=~/code/nestbox/config/armdemo_config.yaml
python ~/code/nestbox/python/nestbox/test_toplevel_setup.py
sleep 5   # give it a few seconds to converge
python -c "import nestbox; print(nestbox.from_cs('cs1').to_cs('cs2').convert([2,3,4]))"
# expect about [-2, 1, 3]
```

Coordinate-system names are global to a daemon. Restart it (Ctrl-C, then run it again) before rerunning a setup script.

Without `NESTBOX_CONFIG`, the code falls back to `config/example_config.yaml`. That config uses the older Adam aligner
over a Unix socket at `~/.nestbox/socket/daemon.sock`.

## 6. Browser visualizer *(not verified)*

**macOS trap:** port 5000 belongs to the AirPlay Receiver, and both the visualizer and the Electron app hard-code
port 5000. Turn the receiver off under System Settings → General → AirDrop & Handoff → AirPlay Receiver.

With Redis and the daemon running:

```bash
cd ~/code/nestbox/visualizer/flaskapp
python app.py          # then open http://localhost:5000
```

## 7. Desktop (Electron) app *(partly verified)*

`npm ci` installs cleanly. The app itself hasn't been run recently.

```bash
cd ~/code/nestbox/desktop/electron-app
npm ci
npm start
```

In dev mode, `src/main.js` starts its own `redis-server` and expects a **PyInstaller-built** daemon at
`python/nestbox/dist/daemon_server`. That file isn't in the repo, and nothing here builds it. You can build it with
`pip install pyinstaller` and PyInstaller on `nestbox/networking/daemon_server.py`, or start the daemon by hand as in
section 5 and ignore the spawn error. The AirPlay port note above applies here too.

## 8. C# client

```bash
cd ~/code/nestbox/csharp
dotnet build Nestbox.sln
dotnet build Nestbox.sln   # yes, twice
```

The **first build fails** with `The type or namespace name 'Protos' does not exist`. That's because the `PreBuild`
step only runs `protoc` (which must be on your PATH) to write `Nestbox.Protos/Generated/Twig.cs` after MSBuild has
already listed the files to compile. The second build picks it up and succeeds. Expect warnings, including NU1903
for `System.Text.Json` 8.0.3.

`dotnet run --project Nestbox.App -f net8.0` must be started from a directory that contains `config/config.yaml`.

## 9. Quest / arm demo (optional, hardware)

Sections 1–8 don't need anything outside this repo. The arm demo does:

- **Demo scripts:** in the `labspace` repo, on branch **`armdemo-nestbox`**: `demo/follow_hand.py --nestbox`,
  `nestbox_link.py`, `run_nestbox_demo.sh`, the camera-ray test, and calibration data in `demo/data/`. That branch is
  matched to `armdemo` here. `main` of labspace doesn't have the nestbox integration.
  ```bash
  cd ~/code && gh repo clone dgretton/labspace && cd labspace && git checkout armdemo-nestbox
  ```
  `python/nestbox/test_armdemo_alignment.py` reads `labspace/demo/data/hand_cal.json` by default, through a path relative
  to the current directory. Pass `--truth ~/code/labspace/demo/data/hand_cal.json` to point it there.
- **Quest app:** Unity project `NestboxHand` (Unity 2021.3.13f1), plus the overlay scripts and the prebuilt APK in
  Dana's `arm-demo-20261003/` folder. None of these are in git. Ask Dana for a copy.

To work on them you also need:

```bash
brew install --cask android-platform-tools   # adb, for `adb reverse tcp:8650 tcp:8650` etc.
brew install --cask unity-hub                # then install Unity 2021.3.13f1 + Android Build Support from the Hub
brew install --cask tailscale                # the RoArm's Pi is reached over Tailscale
```

See `docs/ARM_DEMO_INTEGRATION.md` for how the pieces connect, plus the known Unity and adb traps.

## Day-to-day cheat sheet

```bash
cd ~/code/nestbox && source .venv/bin/activate
export NESTBOX_CONFIG=$PWD/config/armdemo_config.yaml
sh protoc_python.sh                      # after editing protos/twig.proto
(cd python && python -m pytest -q nestbox/test_gauss_newton_aligner.py nestbox/test_bearing_measurement.py nestbox/test_twig.py nestbox/test_optimized_transformer.py)
redis-server --save "" --appendonly no   # separate terminal
python -m nestbox.networking.daemon_server --config-path "$NESTBOX_CONFIG"   # separate terminal
```
